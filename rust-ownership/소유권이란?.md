## 프로그램 메모리 관리
- GC를 이용하는 언어들 - Java, Go, Python, JavaScript
- 수동으로 프로그래머가 메모리를 관르 - C, C++
- 컴파일 시점에 메모리 관리 규칙을 검사 - Rust

### Garbage Collector 활용방식
- Java, Python, JavaScript, Go  등에서 활용
- 실행 시간 중에 때때로 더이상 쓰지 않는 메모리를 정리
- 개발하기 (대단히) 편리
- 운영할 때 성능상 문제가 되기도 (대부분의 경우 OK)

### 수동 메모리 관리
- C, C++
- 개발자가 메모리 할당과 해제 작업을 지시
- 최적의 속도. 실행시 메모리 관리 부담 최소
- 개발하기 힘듦. 실수 및 버그의 온상.

## 제 3의 방법 - Rust의 메모리 관리
- 소유권 규칙에 따라 컴파일 시점에 메모리 할당/해제 관리
- 규칙에 어긋나면 컴파일되지 않음
- 규칙을 잘 지키면 컴파일러가 잘 처리해줌
- 실행시간 손해가 없으면서, 실수할 여자가 없음 (rust의 강점)

### 변수의 범위 scope가 끝나면 메모리 해제 가능

## 문자열 리터럴과 String
- 기본 테이터 타입은 Stack에서 쉽게 관리 가능
- 문자열 리터럴 string literal은 프로그램에 '고정'으로 확보
- 문자열 리터럴은 불변 immutable
- 사용자가 입력하는 문자열은 어떻게?

### 문자열 String 타입
- 변경 가능한 mutable - 길이가 늘어날 수 있음
- 컴파일 시점에 크기를 알 수 없음
- 힙 메모리 차지해야 함

```rust
fn main() {
    // let s = "헬로"; << &str (스트링 리터럴, immutable)
    let mut s: String = String::from("헬로"); // 스트링 (mutable)
    s.push_str(", 월드");
}
```

### 문자열 String 타입 메모리 할당
- 실행 시점에 메모리 할당 요청
- 메모리 할당한 문자열을 다 쓰고 나면?
- 사용가능한 범위가 끝나면, 값도 제거된다.

## 소유권 규칙
- Rust에서 모든 값은 소유자(owner)가 있다.
- 한 시점에 딱 하나의 소유자만 있을 수 있다.
- 소유자의 범위가 끝나면, 값도 제거된다.

```rust
fn main() {
    {
        let x = 3;
        let y = x; // x가 복사 y도 3이 들어 있음
        println!("x = {x}, y = {y}");
    }
}
```
```rust
fn main() {
    {
        let s1 = String::from("헬로"); // heap
        let s2 = s1; // 이때, "헬로"는 s2로 소유권이 넘어감
        println!("s2 = {}", s2);
        println!("s1 = {}", s1); // s1은 소유권이 없기 때문에 안됨
    }
}
```
둘 다 쓰고 싶다면
```rust
fn main() {
    let s1 = String:from("헬로");
    let s2 = s1.clone(); // 힙 메모리 안에 값을 복제

    // 이 경우 둘 다 가능
    println!(s1);
    println!(s2);
}
```

### 기본 데이터 타입 Copy | Stack에만 자리하는 값
| Copy 여부 | 타입 예시                                      |
| ------- | ------------------------------------------ |
| O       | 모든 정수 타입 (`i32`, `u32`, `i64` 등)           |
| O       | `bool`                                     |
| O       | `char`                                     |
| O       | 부동소수점 타입 (`f32`, `f64`)                    |
| O       | 구성 요소가 전부 `Copy`인 튜플: `(i32, bool)`        |
| X       | `Copy`가 아닌 요소가 하나라도 있는 튜플: `(i32, String)` |

## 함수 호출 시 소유권 이동
```rust
fn main() {
    // 함수 호출로 s를 넘기면 string_length로 소유권이 넘어간다.
    let s = String::from("헬로");
    string_length(s);
    // println!(s); << 이거 불가능

    // 기본 데이터 타입은?
    let x = 3;
    double(x);
    println!("x = {x}"); //이건 가능

}

fn string_length(s: String) {
    println("문자열 s의 길이는 : {}", s.len());
}

fn double(s: i32) {
    println!("x = {}", x);
}
```
### 함수 반환값의 소유권 이동
```rust
fn main() {
    let s1 = String::from("헬로");
    let s2 = string_length(s1); // 반환되면 소유권이 main으로 돌아옴
    println!("s = {}", s2);
}

fn string_length(s: String) -> String {
    println!("s의 길이는 = {}", s.len());
    s
}
```
### 불필요한 소유권 이동 문제
```rust
fn main() {
    let s = String::from("헬로");
    let (let, s) = string_length(s);
    println!("문자열 s={} 의 길이는 = {}", s, len);
}

fn string_length(s: String) -> (usize, String) {
    println!("s = {}", s);
    (s.len(), s)
}
```
이 경우, 불필요하게 s가 string_length에 넘어갔다가 다시 main으로 돌아오는 문제가 생긴다.
이를 해결하기 위해 borrow(임대)를 사용할 수 있다.

### 참조는 기본적으로 immutable
빌려준 변수는 기본적으로 immutable이기 때문에 바꿀 수 없다.
```rust
fn main() {
    let s = String::from("헬로");

    append_word(&s);

    println!("s = {}", s);
}

fn append_word(s: &String) {
    s.push_str(", 월드"); // 안됨
}

```

때문에 참조값도 mutable하게 전달할 수 있다

```rust
fn main() {
    let s = String::from("헬로");

    append_word(&mut s);

    println!("s = {}", s);
}

fn append_word(s: &mut String) {
    s.push_str(", 월드"); // 이게 됨!
}
```

### 변경가능한 참조 mutable reference 제약조건
- mutable reference를 만들면, 추가 참조는 만들 수 없다.

```rust
fn main() {
    let mut s = String::from("헬로");

    let r1 = &mut s; // mutable 참조 1
    let r2 = &mut s; // mutable 참조 2

    println!("r1 = {}, r2 = {}", &r1, &r2); // 문제!!
}
```

### 데이터 경쟁조건 data race
- 둘 이상의 포인터가 같은 데이터를 참조
- 한 개 이상의 포인터가 데이터를 쓰려고 접근
- 해당 데이터 접근을 동기화할 방법이 없음
- Rust는 아에 컴파일 타임에 데이터 경쟁조건을 방지!

### 참조 여러번 &mut -> 불가능
```rust
fn main() {
    let mut s = String::from("헬로");
    {
        let r1 = &mut s;
    }
    let r2 = &mut s; // 이 경우는 문제가 없음
}
```
```rust
fn main() {
    let mut s = String::from("헬로");

    let r1 = &s; // 일반 불변 참조 1
    let r2 = &s; // 일반 불변 참조 2
    println!("r1 = {}, r2 = {}", &r1, &r2);

    let r3 = &mut s; // mut 참조
    println!("r1 = {}, r2 = {}, r3 = {}", &r1, &r2, &r3); // 이건 안됨!
}
```
r3(mutable 참조)를 만드는 순간 다른 참조는 사용할 수 없게 됨!!

### 참조 여러번 + &mut -> 범위가 겹치지 않으면 가능
```rust
fn main() {
    let mut s = String::from("헬로");

    let r1 = &s; // 일반 불변 참조 1
    let r2 = &s; // 일반 불변 참조 2
    println!("r1 = {}, r2 = {}", &r1, &r2);

    // 여기까지가 r1, r2의 쓰임이 끝남

    let r3 = &mut s; // mut 참조
    println!("r3 = {}", &r3); // 가능! r1, r2를 접근하지 않으면 됨.
    println!("r1 = {}", &r1); // 이건 안됨!
}
```

### 만약 문자열의 특정 범위 인덱스값을 쓴다면?
- 그 범위 값에서 문자열로 만드는 것도 번거롭지만
- 원래 문자열이 메모리에서 사라진다면?
- 아니면 원래 문자열이 중간에 값이 바뀐다면
- 인덱스 범위값이 무효화됨

```rust
fn main() {
    let s = String:from("헬로 월드");

    let word = &s[0..6]; // 헬로
    let word: &str = &s[7..13]; // 월드

    println!("word = {}", word);
}
```

### first_word(s) -> &str
```rust
fn main() {
    let s = String:from("헬로 월드");

    let word = first_word(&s);

    println!("word = {}", word);
}

fn first_word(s: &String) -> &str {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[..i];
        }
    }

    &s[..]
}
```
### 문자열 리터럴은 사실 슬라이스
```rust
fn main() {
    let hello: &str = "헬로";
    let s = String::from("헬로 월드");
    let word = first_word(hello); // 가능
    let word = first_word(&s);    // 가능

    println!("hello = {}, word = {}", hello, word);
}

fn first_word(s: &str) -> &str {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[..i];
        }
    }
}
```
